# Project Conventions — ssl-repository profile

> Installed by `install.sh` (profile **ssl-repository**): projects created with [ssl_cli](https://pub.dev/packages/ssl_cli)
> using the **Repository** (pattern 2) or **Bloc** (pattern 3) structure — `lib/modules/<module>/…`.
> This file describes the structure ssl_cli generates. Real projects evolve: `/bootstrap` checks it against the code and
> records differences in `.claude/rules/PROJECT_NOTES.md` (yours, never overwritten). **Where the code differs, follow the code
> and PROJECT_NOTES.md.**
> Moving this project to Clean Architecture? Use `/migrate` — never mix the two structures ad hoc.

---

## Stack (as generated by ssl_cli)

| Concern | Choice |
|---------|--------|
| HTTP | Dio via `lib/data_provider/api_client.dart` → `ApiClient().request(url:, method: Method.GET…, params:, onSuccessFunction:)` |
| GraphQL (if used) | `lib/data_provider/graph_client.dart` |
| Local storage | `PrefHelper` (`lib/data_provider/pref_helper.dart`, shared_preferences) — **never store tokens/PINs here if the project has secure storage** |
| URLs / keys | `lib/constant/app_url.dart` (`AppUrl` enum), `lib/constant/constant_key.dart` |
| State | Module `controller/` (plain class, Riverpod, Provider or GetX — see STATE_MANAGEMENT.md) or `bloc/` (pattern 3, flutter_bloc) |
| Navigation | `Navigation.push(context, appRoutes: AppRoutes.x)` (`lib/utils/navigation.dart`, `lib/utils/app_routes.dart`) |
| UI kit | `lib/global/widget/` — `GlobalText`, `GlobalButton`, `GlobalAppBar`, `GlobalTextFormField`, `GlobalDropdown`, `GlobalLoader`, `GlobalImageLoader`, `GlobalSvgLoader`, `ErrorDialog` |
| Styles | `KColor.x.color` (`k_colors.dart`), `k_text_style.dart`, `k_assets.dart`, `flutter_screenutil` (`.w .h .sp .r`) |
| Feedback | `ViewUtil.SSLSnackbar(msg)`, `ViewUtil.showAlertDialog(...)` |
| Localization | `lib/l10n/intl_en.arb`, `intl_bn.arb` |

## Architecture & Folder Layout

```
lib/
├── constant/          app_url.dart · constant_key.dart
├── data_provider/     api_client.dart · graph_client.dart · pref_helper.dart
├── global/
│   ├── model/         global_response.dart · global_paginator.dart · graph_ql_error_response.dart
│   └── widget/        Global* widgets · error_dialog.dart
├── l10n/
├── modules/
│   └── <module>/
│       ├── controller/          <module>_controller.dart   (pattern 2)
│       │   └── state/           <module>_state.dart
│       ├── bloc/                <module>_bloc.dart · _event.dart · _state.dart   (pattern 3)
│       ├── model/               <name>_model.dart / response models
│       ├── repository/          <module>_api.dart · <module>_interface.dart · <module>_repository.dart
│       └── views/               <module>_screen.dart
│           └── components/      module-only widgets
├── utils/             navigation.dart · app_routes.dart · view_util.dart · extension.dart · enum.dart · network_connection.dart · date_util.dart
│   └── styles/        k_colors.dart · k_text_style.dart · k_assets.dart · styles.dart
└── main.dart
```

## Layer Rules

| Layer | File | May call | Must not |
|---|---|---|---|
| View | `views/*_screen.dart`, `views/components/` | its controller / bloc, Global widgets, `Navigation`, `ViewUtil` | call `ApiClient` or repositories directly; hold business logic |
| Controller / Bloc | `controller/*_controller.dart` or `bloc/*_bloc.dart` | `I<Module>Repository` | build widgets; call `ApiClient` directly |
| Repository | `repository/*_repository.dart` implements `repository/*_interface.dart` | `<Module>Api`, models | know about widgets / BuildContext |
| Api | `repository/*_api.dart` | `ApiClient().request(...)` with `AppUrl` + `Method` | parse UI state |

Modules talk to each other only through shared code in `global/` or `utils/` — never import another module's `views/`.

## Naming
- Module folder and files: `snake_case` (`my_account/controller/my_account_controller.dart`)
- Classes: `MyAccountController`, `IMyAccountRepository`, `MyAccountRepository`, `MyAccountApi`, `MyAccountScreen`
- Tests mirror paths: `test/modules/my_account/controller/my_account_controller_test.dart`

## Shared Widgets & UI
- Never raw `Text`, `ElevatedButton`, `TextFormField`, `AppBar`, `CircularProgressIndicator`, `Image.asset` in `lib/modules/` → use the `Global*` widgets.
- Colors only via `KColor.<name>.color`; assets via `k_assets.dart`; sizes via ScreenUtil.
- Snackbars via `ViewUtil.SSLSnackbar(...)`, dialogs via `ViewUtil.showAlertDialog(...)`.

## Error Handling
`ApiClient` handles no-internet, `DioException` and non-2xx centrally (`_handleNoInternet`, `_handleDioError`, `_handleResponse`) and shows global dialogs.
Repositories return parsed models from `onSuccessFunction`; controllers decide what the UI shows. Don't add a second error-dialog path in modules.

## Dependency Injection
Created directly (`final _repo = DashboardRepository();`) unless PROJECT_NOTES.md says the project added a locator/provider.

## Secrets
URLs/keys live in `constant/` and flavor config — never hardcode credentials; prefer the project's secure mechanism (see PROJECT_NOTES.md / SECURITY.md).

## Testing
`flutter_test` + `mocktail`. Mock `I<Module>Repository` for controllers/blocs; mock `<Module>Api` (or `ApiClient`) for repositories.

## New Feature Checklist (used by `/feature`)
1. `ssl_cli module <name>` → choose **2 for Others** (Repository pattern) — or **1 for Bloc pattern** if the project uses `bloc/` folders. Never choose 3 (Clean Architecture) in this project unless you're running `/migrate`.
2. Add the endpoint to `AppUrl` (`lib/constant/app_url.dart`).
3. `<module>_api.dart`: one method per endpoint using `ApiClient().request(url:, method:, params:, onSuccessFunction:)`.
4. `<module>_interface.dart` (contract) → `<module>_repository.dart` (implements it, maps JSON to models).
5. Controller / bloc + state; screen in `views/`, module-only widgets in `views/components/`.
6. Route in `AppRoutes` + `app_routes.dart`; navigate with `Navigation.push`.
7. New strings in `intl_en.arb` / `intl_bn.arb`; new assets → `ssl_cli generate k_assets.dart`.

## Do / Don't
- ✅ Copy the structure of the closest existing module before writing a new one.
- ✅ Reuse `global/widget` and `utils/` helpers; add a new shared widget there only if two modules need it.
- ❌ No `print()` — use the project logger; never log tokens, PINs, account numbers, NID or full responses.
- ❌ Don't introduce Clean Architecture folders (`data/ domain/ presentation/`) piecemeal — use `/migrate`.
